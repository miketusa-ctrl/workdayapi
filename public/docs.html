API reference

Base URL {{ORIGIN}}. All responses are JSON with CORS enabled. Dates are plain calendar dates (YYYY-MM-DD), with no time zones. Supported years: 2020-2035.

Authentication and limits

  • Anonymous (no key): about 30 requests per minute per IP. Meant for trying the API and for the web calculator.
  • API key: send Authorization: Bearer wd_live_… (or X-Api-Key). Free keys include 1,000 calls per calendar month (UTC) and about 120 requests per minute per key (and per IP for keyed traffic). Responses carry X-Plan, X-Quota-Limit, X-Quota-Used and X-Quota-Remaining. When the monthly quota is used up you get 429 monthly_quota_exceeded with Retry-After = seconds until 00:00 UTC on the 1st.
  • Repeated failed authentication (malformed, unknown or revoked keys) from one IP is limited to about 10 per minute; after that the IP gets 429 too_many_auth_failures for a minute. If the service-wide daily capacity for failed key lookups is used up, a client that failed authentication within the last minute may get 503 daily_capacity_reached with Retry-After: 60; retry in a minute (the condition clears a minute after that client's last failed attempt). Clients without recent failures are not affected. While an IP is marked, a valid key it has not used recently also counts once toward its 10 per minute.
  • Get a free key: curl -X POST {{ORIGIN}}/v1/keys (the key is shown once). Check usage: GET /v1/key. Sign-ups are limited to about 5 per minute and 5 per UTC day per IP (IPv6: per /64, and 15 per day per /48): 429 rate_limited (Retry-After: 60) or 429 signup_limit_reached (until 00:00 UTC).
  • Request bodies are capped at 16 KB (413 payload_too_large). On GET endpoints only successful calls count toward your quota (validation errors are free). POST /v1/batch charges one call per submitted op, including ops that return an error.
  • Send each query parameter once: a repeated parameter (e.g. country=US&country=DE) is rejected with 400 duplicate_parameter.
  • Responses for the same inputs are deterministic and cacheable (Cache-Control: max-age=86400).

Common parameters

ParameterMeaning
countryISO 3166-1 alpha-2 code, e.g. US, DE. See GET /v1/countries.
regionOptional ISO 3166-2 subdivision where supported: DE-BY, GB-SCT… (BY also works). GB defaults to GB-ENG (England and Wales).
weekendOptional override, e.g. fri,sat, sun or none. Default sat,sun.
typesHoliday types that are non-business days. Default public,bank; use public to ignore "bank" days (customary closures such as Christmas Eve in Sweden). observance days never block business days, so a list without public or bank (e.g. types=observance) is rejected with 400 invalid_types on the business-day endpoints (it is fine on /v1/holidays).

Endpoints

GET /v1/holidays

country, year, optional region, types. Lists the year's holidays. Moved holidays carry observed (for example a Saturday 1 January observed on Friday 31 December appears in both years).

curl "{{ORIGIN}}/v1/holidays?country=DE&year=2027&region=DE-BY"
{ "country": "DE", "region": "DE-BY", "year": 2027, "count": 12,
  "holidays": [ { "date": "2027-01-01", "name": "New Year's Day", "local_name": "Neujahr", "type": "public", "national": true }, … ] }

GET /v1/is-business-day

date, country, optional region, weekend, types.

curl "{{ORIGIN}}/v1/is-business-day?date=2026-12-28&country=GB"
{ "date": "2026-12-28", "business_day": false, "reason": "observed_holiday",
  "holiday": { "name": "Boxing Day (observed)", "type": "public", "actual_date": "2026-12-26" },
  "previous_business_day": "2026-12-24", "next_business_day": "2026-12-29", … }

reason is one of business_day, weekend, holiday, observed_holiday. At the edges of the supported range (2020-01-01, 2035-12-31) a neighbour that would fall outside it is null.

GET /v1/add

date, days (integer, negative counts backwards, |days| ≤ 2500), country, optional region, weekend, types. The start date itself is never counted; days=0 returns the date if it is a business day, otherwise the next one.

curl "{{ORIGIN}}/v1/add?date=2026-12-22&days=5&country=US"
{ "date": "2026-12-22", "days": 5, "result": "2026-12-30", "result_weekday": "wednesday", "calendar_days": 8,
  "skipped_holidays": [ { "date": "2026-12-25", "name": "Christmas Day", "type": "public" } ], … }

GET /v1/between

from, to, country, optional inclusive=true, region, weekend, types. Counts the days after from up to and including to (so between(from, add(from, n)) = n); inclusive=true also counts from. If to is before from the counts are negative. holiday_days counts holidays (including any on weekends); weekend_days counts the other weekend days.

curl "{{ORIGIN}}/v1/between?from=2026-12-01&to=2026-12-31&country=FR"
{ "business_days": 21, "calendar_days": 30, "weekend_days": 8, "holiday_days": 1, "holidays": [ … ] }

POST /v1/batch Pro key

Up to 100 operations per call (each submitted op counts as one call, including ops that return an error), using at most 10 distinct calendars (a calendar = country + region + types + weekend). Body ≤ 16 KB. Batch responses are compact JSON; per-day lists (holidays for between, skipped_holidays for add) are replaced by holidays_count / skipped_holidays_count unless the op sets "details": true (at most 10 ops per batch). Errors: 422 too_many_ops, too_many_calendars, too_many_details (rejected batches are not charged).

curl -X POST {{ORIGIN}}/v1/batch -H "Authorization: Bearer $KEY" -H "content-type: application/json" \
  -d '{"ops":[{"op":"add","date":"2026-10-05","days":10,"country":"US"},{"op":"between","from":"2026-01-01","to":"2026-12-31","country":"DE","region":"DE-BY"}]}'
{ "count": 2, "results": [ { "index": 0, "ok": true, "result": { … } }, { "index": 1, "ok": true, "result": { … } } ] }

GET /v1/countries, GET /v1/meta, GET /health

Supported countries with regions, scope, notes and official sources; service version, data version and limits.

Data, sources and disclaimer

Data provided as-is, without warranty. Holidays are computed from rules (fixed dates, Easter, n-th weekday, substitute-day rules) that WorkdayAPI wrote from official government sources; no third-party holiday dataset is bundled. Governments sometimes declare one-off holidays at short notice and many rules have regional exceptions, so verify critical deadlines with the official source. WorkdayAPI is not legal, payroll or financial advice; do not rely on it alone for statutory, payroll, tax or contractual deadlines. Types: public = statutory holiday; bank = not statutory but banks/most businesses are closed (counted as non-business by default); observance = informational, still a business day. Entries marked "predicted": true follow past government practice but have not been officially declared for that year yet (e.g. South Africa's Tuesday substitute when Christmas falls on a Sunday).
